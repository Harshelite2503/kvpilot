# Record a completed VM experiment without changing the experiment

The 28 October P100 full and successful smoke runs are already preserved from the archive supplied to the Mac. **The VM does not need to push those results again.** Their record directories and analysis are listed in the [results audit](p100-results-2026-10-28.md).

`scripts/record_p100_results.sh` is for future completed runs or an optional separate VM-origin record. It needs only Git and Python 3.11+, defaults to `.venv-p100/bin/python`, and does not load model weights, install packages or run inference.

## Update this VM's existing experiment branch

From the known checkout, run this block after the Mac changes have been pushed. The branch check prevents applying the update to a different checked-out branch; fast-forward mode refuses divergent history.

```bash
(
  set -euo pipefail
  cd /home/nutanix/kvpilot-p100
  test "$(git branch --show-current)" = "feat/p100-owned-cache-benchmark"
  git pull --ff-only origin feat/p100-owned-cache-benchmark
)
```

## Optional separate record of the run already on this VM

This creates a fresh `results/p100-vm-<timestamp>` record and publishes it on a branch with the same name. It duplicates the already preserved full-run observations; it is not another experiment. Use it only if a separate VM-origin record is desired.

```bash
(
  set -euo pipefail
  cd /home/nutanix/kvpilot-p100
  KVPILOT_RUN="$(cat results/local-p100-retry-2Lof8g/full-directory.txt)"
  KVPILOT_RECORD_ID="p100-vm-$(date -u +%Y%m%d-%H%M%S)"

  bash scripts/record_p100_results.sh "$KVPILOT_RUN" \
    --record-id "$KVPILOT_RECORD_ID" \
    --source-commit fac2ed29beb602b67725417b6b2f384a14ea5aa7 \
    --push
)
```

Omit `--push` to package locally. The script prints the record path and audit result. Pushing uses the VM's existing Git identity and remote access; it does not configure credentials. On the Mac, add `--python .venv/bin/python` or an explicit Python 3.11+ executable.

## Future runs

Record the tested commit before execution, alongside the run directory. Use a fresh record ID and pass that original commit even after updating the checkout:

```bash
bash scripts/record_p100_results.sh /path/to/completed-run \
  --record-id p100-next-experiment-v1 \
  --source-commit ORIGINAL_TESTED_COMMIT \
  --push
```

`ORIGINAL_TESTED_COMMIT` is a placeholder to replace, not a literal command argument. A commit is accepted only when every source hash in the frozen protocol matches that commit's files. A hash-compatible revision is not independent proof of physical execution; the original benchmark did not automatically record its Git commit.

## What the script does

1. Reads only the known benchmark artifacts listed in `artifact-sha256.json`, verifies their hashes, and snapshots their bytes.
2. Checks every frozen source SHA256 against the supplied Git commit, then runs the independent validator on that byte snapshot.
3. Creates `run.tar.gz` with deterministic headers and the unchanged artifacts under `run/`; writes `record.json`, `record-sha256.json`, `validation.json`, and the original `report.md` alongside it.
4. Refuses to overwrite a different record. Existing records are reused only if all generated bytes match; use a fresh ID if recorder/compression versions differ.
5. With `--push`, creates `results/<record-id>` from the current HEAD in a temporary Git worktree, commits **only** the new record directory, and performs an ordinary non-force push. The original checkout branch, index and staged/unstaged files are untouched. The new branch inherits current HEAD's history.

The file allowlist excludes parent-directory logs, model weights, `.env`, unrelated files and virtual environments. Model-directory paths inside the original frozen metadata are preserved. If a future benchmark schema adds artifacts, the recorder intentionally refuses it until the allowlist is updated and tested.

The script never merges a branch or opens a PR. A failed publication retains the temporary checkout and reports its path so the commit can be recovered; it does not reset or delete user work. If the exact record is already committed at HEAD, it reports that fact and creates no additional branch. A new record ID should identify a new record, never silently replace earlier evidence.

## Verify a checked-in record locally

From the repository root:

```bash
KVPILOT_VERIFY_DIR="$(mktemp -d)"
tar -xzf results/p100-2026-10-28-full/run.tar.gz -C "$KVPILOT_VERIFY_DIR"
.venv-p100/bin/python scripts/validate_p100_results.py "$KVPILOT_VERIFY_DIR/run"
```

The outer `record-sha256.json` binds the package and provenance; the inner `artifact-sha256.json` binds the exact raw run files. Neither is a digital signature or a performance/quality certification.
